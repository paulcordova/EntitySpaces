# Contributing to EntitySpaces

Thanks for taking the time to contribute. This document explains how to report a problem, how to
submit a change, and what you are agreeing to when you do.

There is **no copyright assignment** and no separate contributor license agreement. You keep the

## Developer Certificate of Origin (DCO)

Every commit must carry a `Signed-off-by` line certifying the Developer Certificate of Origin 1.1:

```
Signed-off-by: Your Name <your.email@example.com>
```

Add it automatically with:

```bash
git commit -s -m "fix(mysql): correct parameter binding on empty insert"
```

By signing off you certify that:

1. You created the contribution, in whole or in part, and have the right to submit it under the
   project's license; **or** it is based on previous work that is covered by the same license and you
   have the right to submit it.
2. You understand the project is public and that your contribution, with your name and email, will be
   recorded permanently in the repository history.

If your employer has rights over work you produce, you confirm you have permission to contribute, or
that your employer has waived those rights.

Contributions without a sign-off will be asked to amend the commit. Do not be discouraged by that —
it is a one-line fix.

## What is welcome

| Type | Notes |
|---|---|
| Bug reports | Include the provider, the database engine and version, the driver version, and the target framework. A failing test is worth more than a description. |
| Test cases | Especially against schemas that exercise naming divergence, composite keys, identity strategies and concurrency. |
| Documentation fixes | Typos, wrong commands, outdated version numbers. |
| Provider fixes | With a test that fails before the change and passes after. |
| Template fixes | C# and VB.NET templates must stay aligned; a change to one usually needs the other. |

## What to discuss first

Open an issue before starting work on:

- A new database provider.
- A change to the public API of `esEntity`, `esEntityCollection` or the query API.
- A change to the SQL generated by a provider.
- Anything that alters the shape of generated code — this breaks every user's regeneration workflow.

## Reporting a bug

Please include:

1. **Provider and engine**: SQL Server 2022, PostgreSQL 18, MySQL 8.0.28, SQLite 3.46, Oracle 19c.
2. **Target framework**: `net48`, `net8.0`, `net9.0` or `net10.0`.
3. **Driver and version**: Microsoft.Data.SqlClient 7.1.1, Npgsql 10.0.3, MySqlConnector 2.6.2, etc.
4. **Package version**: the `2026.11.0` line, not "latest".
5. **Minimal reproduction**: the entity, the operation, and the generated SQL if you can capture it.
6. **Whether it reproduces with a fresh schema** or only with your existing one.

Two facts speed up diagnosis enormously: the SQL that was generated, and whether the same operation
works with a different provider.

## Pull requests

- Branch from `master`. Name it something descriptive: `fix/postgres-concurrency-update`.
- One topic per pull request. A formatting sweep mixed with a behaviour change will be asked to split.
- Keep the existing code style. The codebase targets C# 7.3 for the `net48` build: no newer syntax in
  code compiled into the packages.
- Do not reformat unrelated lines. It makes the diff unreviewable.
- Update the relevant `README-<PROVIDER>.md` if behaviour changes, and `CHANGELOG.md` under
  `[Unreleased]`.
- Add or update tests. A fix without a test will be held until one exists.

## Code of conduct

Assume good faith. Critique the code, not the person. Technical disagreement is welcome; hostility is
not. Reports of abusive behaviour can be sent to the maintainer privately and will be handled
confidentially.
